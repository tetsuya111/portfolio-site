# 要件定義: 詳細表示ページ（alltime.php 等）から曲名を直接取り出す

元の要望: [issue #3「[spotify] 詳細表示ページ（alltime.php 等）から曲名を直接スクレイピングする」](https://github.com/tetsuya111/portfolio-site/issues/3)
対象: [portfolios/spotify-billboard-playlist/](../../../portfolios/spotify-billboard-playlist/)（既存仕様: [docs/specs/spotify-billboard-playlist/](../spotify-billboard-playlist/requirements.md)）

## 前提と仮定

issue 本文と既存コードから推定し、無人実行のため次のとおり判断した。覆したい場合はこの節を起点に修正する。

| # | 仮定 | 根拠 |
|---|---|---|
| A1 | 「詳細表示形式のページ」は、`<script>` 内に `$('#data-table').append(…)` で曲の行を埋め込んでいるページすべてを指す。`alltime.php` に限らず、同じ形式なら `no1weeks.php` なども対象になる | issue が「alltime.php **等**」と書き、`chart.php` も同じ形式と述べているため。ページ名で判定すると、同じ形式のページが増えるたびに改修が要る |
| A2 | `chart.php?date=…` は今までどおり同じ日付の `dispHot100.php`（100曲）に置き換えて取得する | issue が「置き換えをやめるかは別に判断する」としており、`chart.php` 側は上位40曲しかないため、置き換えを続けた方が利用者が得る曲数が多い |
| A3 | ページ構造は issue に記載された 2026-11-13 時点の確認結果を正とする。テスト用のHTMLはその記載から手で作る | 実ページの再取得は外部アクセスにあたり、このスキルでは確認なしに行えないため。実ページでの最終確認は実装時に利用者の許可を得て行う |
| A4 | 同じページ内で順位が重複した場合（同順位のタイ）は、後の行を捨てずに順位で並べたうえで「直前の行の順位+1」に繰り下げて残す（例: 1, 2, 2, 4 → 1, 2, 3, 4） | DB の `chart_tracks` は `(source_id, rank)` が主キーで、重複すると保存に失敗するため。2026-11-14 の実ページ確認で `alltime.php?page=1` に正当な同順位（2位が2曲）があり、捨てると成功指標の20曲に届かないため、当初の「後の行は捨てる」から変更した |
| A5 | アーティスト名が取れない行は、アーティスト名を空文字として残す（曲名と順位が取れれば採用） | 既存の `parse_hot100` と同じ扱いにそろえる。曲名だけでも Spotify 検索はできる |
| A6 | API・フロントエンドの変更は不要。曲一覧の形（順位・曲名・アーティスト名）は既存のまま | 既存の `ChartEntry` をそのまま返せば、以降の処理（DB 保存・プレイリスト作成）が変わらないため |

## 背景・課題

今のバッチは簡易表示ページ（`dispHot100.php?date=…`）の `<table>` しか解析できない。`alltime.php`（歴代ランキング）のように、対応する簡易ページがない詳細表示ページは「チャートの曲が見つかりませんでした」で失敗する。そのため、週間チャート以外のランキングからはプレイリストを作れない。

詳細表示ページでは、曲データが HTML 要素ではなく `<script>` 内の `$('#data-table').append("…")` に**文字列として**埋め込まれている（1曲ごとに順位 `div.number`・曲名 `span.title`・アーティスト `span.artistLink`、1ページ20曲、`page=1`〜`6`）。

## ゴール

- 詳細表示ページのURLを登録するだけで、そのページに載っている曲の一覧が取得でき、既存の流れでプレイリストを作れる。

## Non-Goals（やらないこと）

- 複数ページ（`page=1`〜`6`）をまとめて1つのプレイリストにすること
- ホスト制限・HTTPS のみ・リダイレクト非追従・サイズ上限など、既存の取得制約の緩和
- `chart.php` を `dispHot100.php` に置き換える既存動作の変更（A2）
- JavaScript の実行（ブラウザエンジンを使ったページの描画）

## 成功指標

- `alltime.php?page=1`〜`page=6` の各URLから、それぞれ20曲（計120曲）が手作業なしで取得できる。
- 取得した曲名・アーティスト名に、`&amp;` や `\"`・`’` のようなエスケープ表記が1件も残らない。

## ユーザーストーリー

- US1: As a 洋楽リスナー, I want 歴代ランキングなどの詳細表示ページのURLからプレイリストを作りたい, so that 週間チャート以外のランキングも Spotify で聴ける.

## 機能要件（受け入れ基準）

- **R1** WHEN 詳細表示形式のページのURLが登録された THE SYSTEM SHALL 簡易表示ページを経由せず、そのページ自体を取得して曲一覧を作る。
- **R2** WHEN 詳細表示形式のページを解析する THE SYSTEM SHALL `<script>` 内に埋め込まれた行から、順位・曲名・アーティスト名を取り出す。
- **R3** WHEN 1ページから曲を取り出した THE SYSTEM SHALL 順位の昇順に並べて返す（`alltime.php?page=1` では20曲）。
- **R4** IF 詳細表示形式のページから1曲も取り出せない THEN THE SYSTEM SHALL そのURLを失敗としてDBに記録し、詳細表示ページから曲を取り出せなかった旨を理由として保存する。
- **R5** THE SYSTEM SHALL 曲名・アーティスト名に含まれる HTML エンティティ（`&amp;` など）を、表示どおりの文字に戻す。
- **R6** THE SYSTEM SHALL 曲名・アーティスト名に含まれる JavaScript 文字列のエスケープ（`\"`・`\'`・`\\`・`\/`・`\uXXXX`）を、表示どおりの文字に戻す。
- **R7** WHEN 簡易表示ページ（`dispHot100.php`）・`chart.php`・トップページ・同じ表構造を持つその他のページが登録された THE SYSTEM SHALL これまでと同じ結果を返す。

## 非機能要件

- **N1** 取得先ホスト・スキーム・リダイレクト・タイムアウト・応答サイズの制約は既存のまま変えない。
- **N2** 新しいライブラリ（JavaScript 実行環境など）を追加しない。
- **N3** ページ内のスクリプトを実行しない（文字列として読むだけにする）。
