# 要件定義: Billboard Hot 100 から Spotify プレイリストを作成する

元の要望: [memo/spotify_billboard_album.md](../../../memo/spotify_billboard_album.md)

## 前提と仮定

要望メモから推定し、無人実行のため次のとおり判断した。覆したい場合はこの節を起点に修正する。

| # | 仮定 | 根拠 |
|---|---|---|
| A1 | メモの「アルバム」は Spotify の**プレイリスト**を指す | Spotify Web API に一般ユーザーがアルバムを作る機能はなく、メモの参考URLも「Add Items to Playlist」であるため |
| A2 | 曲名の取得元は `billboard.mryogaku.com`（ビルボード・データベース）に限定する | メモの取得先として唯一明記されている。任意ホストを取得するとSSRFの攻撃面になるため |
| A3 | 入力URLとして、同サイトのトップページ・`chart.php?date=…`・`dispHot100.php?date=…`（スマホ版 `/s/php/…` を含む）を受け付ける | トップページはメモに記載のURLそのもの、残り2つは同サイトでチャートを表示するページ（2026-11-13 に実ページで確認） |
| A4 | 作成するプレイリストは非公開（private）とする | 最小権限のスコープ（`playlist-modify-private`）で済むため |
| A5 | 利用者はローカル環境（`http://127.0.0.1`）で動かす開発者本人。本番デプロイは対象外 | ポートフォリオ用途であり、Spotify アプリが開発モードでは登録ユーザーしか使えないため |
| A6 | 「DBに登録されたURLをスクレイピングする」は、受け付けたURLをDB（SQLite）に登録し、バッチがそれを処理する形で実現する | メモの「流れ」節の記述どおり |
| A7 | Spotify 上で見つからない曲はスキップし、結果として利用者に一覧で示す | 一部の曲が見つからないだけで全体を失敗にするのは利用者の利益にならないため |

## 背景・課題

洋楽のヒットチャート（Billboard Hot 100）を Spotify で聴きたいとき、チャートの曲を1曲ずつ検索してプレイリストに追加するのは100曲分の手作業になる。チャートページのURLを渡すだけで、その週の曲を収めたプレイリストができれば、この手間がなくなる。

## ゴール

- チャートページのURLを1つ入力してボタンを1回押すだけで、その週の Hot 100 の曲を含む Spotify プレイリストが自分のアカウントにできる。

## Non-Goals（やらないこと）

- billboard.mryogaku.com 以外のサイト（billboard.com 本家など）からの取得
- 定期実行（cron 等）による自動スクレイピング
- 公開プレイリストの作成、既存プレイリストへの追記・更新
- 複数ユーザー向けの本番運用（デプロイ、永続セッション、利用者管理）
- 曲の照合精度を上げる高度なあいまい検索

## 成功指標

- Hot 100 のチャートURL 1件から、手作業なしでプレイリストが作成できる（操作はURL入力・ボタン押下・初回の Spotify ログインのみ）。
- 一般的な週のチャートで、100曲中 90曲以上が Spotify 上で見つかりプレイリストに追加される。

## ユーザーストーリー

- US1: As a 洋楽リスナー, I want チャートページのURLから曲名の一覧を取得したい, so that 手で書き写さずに済む.
- US2: As a 洋楽リスナー, I want 自分の Spotify アカウントでログインしたい, so that 自分のアカウントにプレイリストを作れる.
- US3: As a 洋楽リスナー, I want 曲名の一覧からプレイリストをワンクリックで作りたい, so that チャートの曲をすぐ聴ける.

## 機能要件（受け入れ基準）

### バッチ（曲名一覧の取得）

- **R1** WHEN 受け付け可能なチャートURLがDBに登録されている THE SYSTEM SHALL そのURLのページを取得し、順位・曲名・アーティスト名の一覧をDBに保存する。
- **R2** WHEN トップページのURLが登録されている THE SYSTEM SHALL ページ内の最新週の Hot 100 全順位ページを特定し、その曲一覧を取得する。
- **R3** WHEN `chart.php?date=YYYY-MM-DD` 形式のURLが登録されている THE SYSTEM SHALL 同じ日付の Hot 100 全順位（最大100曲）を取得する。
- **R4** IF 登録されたURLのホストが `billboard.mryogaku.com` でない THEN THE SYSTEM SHALL 取得を行わず、そのURLを不正として扱う。
- **R5** IF ページの取得または解析に失敗した THEN THE SYSTEM SHALL そのURLを失敗状態としてDBに記録し、失敗理由を保存する。
- **R6** THE SYSTEM SHALL DB上の未処理URLをまとめて処理するバッチを、コマンド1つで実行できるようにする。

### バックエンド

- **R7** WHEN フロントエンドからURLを受け取った THE SYSTEM SHALL そのURLをDBに登録し、バッチ処理で取得した曲名の一覧を返す。
- **R8** IF 受け取ったURLが受け付け可能な形式でない THEN THE SYSTEM SHALL 400 エラーと理由を返す。
- **R9** IF チャートページの取得に失敗した THEN THE SYSTEM SHALL 502 エラーと理由を返す。
- **R10** WHEN ログイン開始を要求された THE SYSTEM SHALL Spotify の認可画面へリダイレクトする。
- **R11** WHEN Spotify から認可コードとともに戻ってきた THE SYSTEM SHALL トークンを取得してログイン状態を作り、フロントエンドへリダイレクトする。
- **R12** IF 認可コールバックの `state` が開始時のものと一致しない THEN THE SYSTEM SHALL ログイン状態を作らずエラーにする。
- **R13** WHEN ログイン状態の照会を受けた THE SYSTEM SHALL ログイン済みかどうかと、ログイン済みなら Spotify の表示名を返す。
- **R14** WHEN ログイン済みの利用者から曲名一覧とプレイリスト名を受け取った THE SYSTEM SHALL 各曲を Spotify で検索し、見つかった曲をチャート順に収めた非公開プレイリストを作成する。
- **R15** WHEN プレイリストを作成した THE SYSTEM SHALL プレイリストのURL・追加した曲数・見つからなかった曲の一覧を返す。
- **R16** IF 未ログインの利用者からプレイリスト作成を要求された THEN THE SYSTEM SHALL 401 エラーを返す。
- **R17** WHEN ログアウトを要求された THE SYSTEM SHALL ログイン状態を破棄する。

### フロントエンド

- **R18** THE SYSTEM SHALL 画面にタイトル、ログイン状態、URL入力欄、作成ボタンを表示する。
- **R19** WHILE ログイン済みである THE SYSTEM SHALL Spotify の表示名とログアウトボタンを表示する。
- **R20** WHILE 未ログインである THE SYSTEM SHALL Spotify ログインボタンを表示し、作成ボタンを押せないようにする。
- **R21** WHEN 作成ボタンが押された THE SYSTEM SHALL 入力URLから曲名一覧を取得し、続けてプレイリストを作成する。
- **R22** WHEN プレイリストの作成が完了した THE SYSTEM SHALL プレイリストへのリンク、追加曲数、見つからなかった曲を表示する。
- **R23** IF 曲名一覧の取得またはプレイリスト作成に失敗した THEN THE SYSTEM SHALL バックエンドが返したエラー理由を画面に表示する。
- **R24** WHILE 処理中である THE SYSTEM SHALL 作成ボタンを押せないようにし、処理中であることを表示する。

## 非機能要件

- **N1（セキュリティ）** Spotify のクライアントシークレット・アクセストークンをブラウザ側に渡さない。
- **N2（セキュリティ）** チャートページの取得は `billboard.mryogaku.com` への HTTPS のみとし、他ホストへのリダイレクトに追従しない。
- **N3（セキュリティ）** 状態を変更するAPI（URL登録・プレイリスト作成・ログアウト）は、フロントエンド以外のオリジンからのリクエストを拒否する。
- **N4（性能）** チャートページの取得は1リクエスト10秒でタイムアウトする。
- **N5（相手先への配慮）** Spotify API から 429 が返った場合は `Retry-After` に従って待ってから再試行する（最大3回）。
- **N6（スコープ）** Spotify に要求する権限は `playlist-modify-private` のみとする。

## スコープ

- 対象: 上記 R1〜R24・N1〜N6
- 対象外: Non-Goals に挙げたもの
