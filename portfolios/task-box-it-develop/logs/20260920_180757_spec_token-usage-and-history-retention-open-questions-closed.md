# 使用量の見える化と対話履歴の保持 の未解決事項を確定

## 何を

`.kiro/specs/token-usage-and-history-retention/requirements.md` の未解決事項のうち3件について、ユーザーの判断を受けて受け入れ基準に反映した。

| 未解決事項 | 決定 | 反映先 |
| --- | --- | --- |
| 残りの使用量の表記 | その日の上限に対する割合（パーセント）で表示する。実数と専門用語は出さない | ストーリー1 基準3・4、基準5（残り0%）、用語集 |
| 「1か月」の起算点 | 対話の作成日時ではなく、最後のメッセージの日時を起点とする | ストーリー3 基準1・3、および継続利用中は超過しないことを基準4として追加 |
| 消去の実行方式 | バッチ処理で実行する。画面の操作を契機に消去する場合も、画面側に別の処理を持たずバッチを起動する | ストーリー3 基準8〜10、依存関係、非機能要件（性能） |

## なぜ

設計（design.md）に進む前に要件を固めるため（`.kiro/specs/README.md` の手順2）。消去処理をバッチに一本化するのは、同じ消去のロジックが画面側とバッチ側に二重に存在することを避けるため。

## 補足

- 未解決事項には、確定に伴って新たに判断が必要になった「残りが少なくなったときの扱い」「割合の丸め方」「バッチの定期実行の方法（インフラ未定のあいだの暫定手段）」を追加した。いずれも design.md で決められる粒度。
- 残りの未解決事項は上記3件と、既存の「保持期間の依頼者への伝え方」「上限引き上げによる費用の見込み」。
