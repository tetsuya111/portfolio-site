# 使用量の見える化と対話履歴の保持 の要件定義を新規作成

## 何を

`.kiro/specs/token-usage-and-history-retention/requirements.md` を新規作成した。ユーザーから出た4つの修正要望を、既存の [hearing-chat-site](../.kiro/specs/hearing-chat-site/requirements.md) に対する変更としてまとめたもの。

- ストーリー1: 残りの使用量を対話画面に表示する
- ストーリー2: 「要件の確定」で項目の充足判定を1回だけにする（LLMの重複呼び出しの削減）
- ストーリー3: 対話履歴は「クリア」と作成から1か月の経過以外では消さない
- ストーリー4: 1日の使用量の上限を現行の5倍（300,000 → 1,500,000トークン / 日）にする

## なぜ

いずれも実装後に見えてきた、継続利用とLLM費用に関する課題への対応。要望が相互に関連する（3つが使用量・費用に関するもの、1つが履歴の保持期間）ため、4件を別々のspecに分けず1つのspecの4ストーリーとして記述した。

## 補足・判断したこと

- 要望どおり「残りのトークンを表示する」を要件に入れたが、CLAUDE.md の「依頼者向けの文言では専門用語を避ける」方針と衝突するため、受け入れ基準では「専門用語をそのまま用いない表記」とし、実数を出すか割合にするかは未解決事項に挙げた。
- 「1か月以上前に作成された」の起算点は、現在の実装では対話（Conversation）が1ユーザーにつき1つで作り直されないため、対話の作成日時を起点にすると利用継続中でも消えてしまう。design.md に進む前に確認が必要な点として未解決事項に明記した。
- 消去の実行方式（定期実行 / アクセス時の判定）は、定期実行の基盤が未整備のため design.md で決めることとした。
- 現時点では requirements.md のみを作成し、design.md / tasks.md は作成していない（`.kiro/specs/README.md` の手順どおり、要件の確認後に進む）。
