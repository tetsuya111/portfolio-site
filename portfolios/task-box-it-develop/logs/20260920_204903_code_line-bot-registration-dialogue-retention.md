# LINE BOTサーバーの登録・対話・履歴・上限・LIFFを実装（タスク6〜9, 11）

## 何を

- **ユーザー情報の登録**（テキスト / LIFF 共通）: フォーマットの解析、名前（1〜50文字）とメールアドレス（形式・254文字）の検証、1アカウント1件のUPSERT。`line_user_id` は署名を検証したWebhookの `source.userId`、またはサーバーで検証したLIFFのIDトークンの `sub` からのみ取得する。再登録しても契約状態は変わらない。
- **LIFF**: `GET /liff`（LINE内で開く登録フォーム。`LIFF_ID` 未設定なら404）と `POST /liff/register`（IDトークンをLINEの検証エンドポイントで検証）。登録処理はテキスト方式と同じ関数を通る。
- **対話**: 受信直後に reply で「しばらくお待ちください」を返し、ジョブでLLMを呼び、回答を Push で送る。返信は200文字程度のプレーンテキストに整形し、金額に触れる場合は案内文へ差し替える。LLMの失敗は「エラーになりました」。
- **会話履歴**: 直近10往復（`HISTORY_MAX_TURNS`）を保存し、超えた分は古い順に削除。他人の履歴は混ざらない。
- **上限**: `users.daily_llm_calls` / `llm_calls_date`（日本時間）で1日30回（`DAILY_LLM_CALL_LIMIT`）。日付が変わると数え直す。
- **保持期間**: `python -m app.cli purge` が、最後のやり取りから24時間を過ぎた履歴と48時間を過ぎた処理済みイベントを消す。件数だけをログに出す。

## なぜ

タスク6〜9と11。契約者だけが対話でき、費用と個人情報の保持を絞ることが要件。

## 実装で判断したこと

- 対話プロンプト（`prompts/dialogue.md`）が無い・空のときは、LLMを呼ばずに仮の応答を返す（設定フラグを増やさない）。design.md の決定どおり。
- 返信の整形で、行頭の箇条書き・見出し・引用の記号と、強調の記号だけを落とす。当初は行頭の数字も落としていたが「2回目」のような文章を壊すため、`1. ` の形のときだけ落とすように直した。
- 金額の抑制は、LLMの回答だけでなく依頼者の質問にも反応させる（「いくら？」に対して金額を出さない）。

## 確認

`python -m pytest` 35件パス（待機メッセージ→Push、仮応答、LLM失敗、整形、金額の差し替え、プロンプトを連結しない、履歴の保存と上限、他人の履歴が混ざらない、上限の到達と日付の切り替わり、purgeの冪等性、`set_contract` 以外で契約状態が変わらないこと、LIFFで偽装した `userId` が使われないこと）。
