# LINE BOTの公開URLの自動設定（ngrok対応）の要件定義を新規作成

## 何を

`.kiro/specs/line-bot-public-url/requirements.md` を新規作成した。4つのユーザーストーリーで構成。

1. **ngrokを使うかの切り替え** — 環境変数1つ（既定は「使わない」）。使う設定なら起動時に公開URLを取得し、使わない設定ならngrok関連の処理を一切動かさない。取得に失敗しても起動は止めない。
2. **LINEのWebhookエンドポイントの自動設定** — 起動時に Messaging API でチャネルのWebhook URLを「公開URL + /webhook」に更新し、疎通確認まで行う。失敗しても起動は止めず、手作業用のURLをログに出す。同じURLなら更新しない。**ngrokを使わない設定では更新しない**（本番設定を上書きしない）。
3. **公開URLの利用箇所の統一** — Webhook・LIFFのリンク・ログが同じ設定値から導かれる。末尾スラッシュの正規化、HTTPS以外への警告。
4. **開発用の機能であることの担保** — 有効時はログに明示、本番相当の設定で有効なら警告、ngrok向けの依存が無くても起動できる。

## なぜ

ローカル開発でngrokのURLが起動のたびに変わり、LINE Developers の画面での貼り替えが毎回発生していた。貼り忘れると「BOTが無反応」になるがログには何も出ず、原因が分かりにくい。ユーザーの指示（環境変数でngrokの使用を決める）に沿って、開発と本番を同じコードで切り替えられる形にした。

## 判断したこと

- `line-bot-server` の修正ではなく、別specとして作成した（1機能=1spec。対象は「公開URLの決め方」に限られ、BOTの機能自体は変えない）。
- 要件としては「起動時に公開URLが決まること」までとし、**ngrokをアプリが起動するのか、別途起動済みのngrokから読むのか**は design.md に送った（未解決事項）。
- 本番でのngrok利用、固定ドメインの契約、ngrokのインストール自動化は Non-Goals に明記した。

## 未解決事項

ngrokの起動主体、LIFFアプリのエンドポイントの自動更新を含めるか、`--reload` のたびに更新APIを呼ばないための判定の持ち方、将来の検証環境の扱い。design.md に進む前に確認する。
