# 管理者の権限の反映の契機を「次回ログイン時のみ」に確定

## 何を

`.kiro/specs/token-usage-and-history-retention/` の3ファイルを更新した。

- requirements.md: ストーリー5 に基準10「変更の反映は対象ユーザーの次のログイン時に行い、ログイン中のユーザーへの即時反映は行わない」を追加。未解決事項から「管理者の権限の反映の契機」を削除し、制約・前提条件に「管理者の入れ替わりは稀で、反映の遅れは支障がない」旨を追記。
- design.md: 主要フロー4 に即時反映を行わないことを明記。`sync_admins` コマンドの位置づけを「即時反映のため」ではなく「ファイルによる指定への切り替え時と、一括で反映したいときのため（定期実行はしない）」に整理。
- tasks.md: タスク1 の完了条件に「ログイン中のユーザーへの即時反映は実装しない」を追加。

## なぜ

ユーザーの判断（即時反映は必要ない）による。管理者は開発者本人のみで入れ替わりが稀なため、反映が次のログインまで遅れても運用上の支障がない。実装を単純にできる。

## 補足

- もう1件の未解決事項「管理者リストのファイルの配置場所」は、インフラ未定のため残している。既定値（`BASE_DIR / "admin_emails.txt"`）と環境変数での変更に対応するため、実装を止める要因にはならない旨を design.md に追記した。
