# 要件定義: コスプレイベント情報まとめサイト（cosplay-event-info）

元の要望: `memo/コスプレのサイト_ポートフォリオ.md`（リポジトリ管理外のメモ）

## 前提と仮定

依頼者への確認なしで作成したため、次の点は推定で決めた。覆す場合はこの節と design.md を更新する。

- **イベントの開催期間を項目に追加する**: メモの項目一覧に日付はないが、「イベントの予定」「イベントの期間で指定できる」という要件から、開始日・終了日が必須と判断した。
- **閲覧は認証なし・読み取り専用**: 情報まとめサイトとして誰でも閲覧できる想定。データの追加はバッチのみで、Web からの書き込み API は作らない（修正は Django 管理画面で行う）。
- **対象サイトの HTML 構造は未確認**: 開発中に対象サイトへアクセスしていないため、サイトごとの抽出ルールは「schema.org の Event（JSON-LD）を優先し、なければサイト別の CSS セレクターで抽出する」作りにし、テストは HTML の固定データで行う。実サイトに合わせたセレクターの調整は運用時に設定で行う。
- **メモの対象サイトで重複している `https://cos-cam.work/` は1件として扱う**。
- **AI による開催場所の補完・正規化は任意機能**: `ANTHROPIC_API_KEY` がある場合だけ Claude API を使い、ない場合・失敗した場合はルールベース（全角半角の統一・都道府県の抽出・主要会場の辞書）で正規化する。API キーがなくても全機能が動くことを優先した。
- **Google マップの表示は API キー不要の埋め込み（iframe）とする**: 期間で絞り込んだ会場の一覧から1件を選ぶと地図に表示する。複数マーカーの同時表示は Maps JavaScript API のキーが必要なため対象外とした。
- **同一判定のしきい値**: 正規化した名前のレーベンシュタイン距離から求めた類似度（1 − 距離 ÷ 長い方の文字数）が、イベントは 0.85 以上かつ開始日が同じ（開催地の都道府県がどちらも判明していて異なる場合は別のイベント）、コスプレイヤーは 0.9 以上で同一とみなす。
- **取得済みページの再取得**: 取得済みの URL は既定で再取得しない。イベント一覧ページのように内容が更新されるページは、バッチの `--force` 指定時だけ再取得する。
- **ポートフォリオサイトへの掲載（`portfolio-site/` への md 追加）はこの要件の範囲外**（別の作業として行う）。

## 背景・課題

コスプレイベントの予定やコスプレイヤーの情報はネット上の複数のサイトに散らばっており、まとめて探せる場所がない。既存のまとめサイトも検索や地図表示がなく簡素なものが多い。イベントに参加したい人・コスプレイヤーを知りたい人が、1か所で検索・比較できるようにする。

あわせて、ポートフォリオとして「Python/DRF のバックエンド」「スクレイピングのバッチ処理」「重複排除」「React/Next.js のフロントエンド」を一通り示す。

## ゴール

- 複数サイトのイベント予定とコスプレイヤー情報を1つの DB に集約し、重複なく閲覧できる。
- イベントを名前・場所・期間で検索でき、開催場所を Google マップで確認できる。
- コスプレイヤーを名前で検索し、詳細なプロフィールを確認できる。

## Non-Goals（やらないこと）

- ユーザー登録・ログイン・お気に入りなどの利用者ごとの機能
- Web 画面からのデータ投稿・編集（管理者は Django 管理画面を使う）
- 対象サイト以外からの収集、収集元サイトの画像の転載
- 複数会場を1枚の地図にマーカー表示すること
- ポートフォリオサイトへの掲載作業

## 成功指標

- バッチを2回続けて実行しても、イベント・コスプレイヤーの件数が増えない（重複・再取得が起きない）。
- 検索 API が、デモデータ（イベント100件程度）で 500ms 以内に応答する。
- テスト（バックエンド・フロントエンド）と lint・build がすべて成功する。

## ユーザーストーリーと受け入れ基準

### イベントの予定

**US-1**: As a イベント参加者, I want 複数サイトのイベント予定を1つの一覧で見たい, so that サイトを回らずに予定を把握できる.

- **EV-1**: WHEN イベント収集バッチを実行したとき THE SYSTEM SHALL 対象サイトのページから、イベント名・リンク・開催場所・開始日・終了日・備考・取得元リンクを抽出して DB に保存する。
- **EV-2**: THE SYSTEM SHALL イベント収集をコマンド1つ（バッチ）で実行でき、対象サイトを指定して実行することもできる。
- **EV-3**: WHEN 抽出したイベントが、既存のイベントと名前の類似度 0.85 以上かつ開始日が同じとき THE SYSTEM SHALL 新しく登録せず既存のイベントに統合し、取得元を追加する。
- **EV-4**: WHEN イベントを保存するとき THE SYSTEM SHALL 開催場所を正規化（会場名・都道府県・住所）して保存する。
- **EV-5**: WHERE AI の API キーが設定されている場合 THE SYSTEM SHALL AI で開催場所の情報を補完・正規化する。
- **EV-6**: IF AI による正規化が失敗したとき THEN THE SYSTEM SHALL ルールベースの正規化結果で保存し、バッチを止めない。
- **EV-7**: THE SYSTEM SHALL イベント一覧画面で、開始日の昇順にイベントを表示する。
- **EV-8**: WHEN 利用者がキーワードを入力して検索したとき THE SYSTEM SHALL イベント名・開催場所・備考のいずれかにキーワードを含むイベントを表示する。
- **EV-9**: WHEN 利用者が期間（開始日〜終了日）を指定して検索したとき THE SYSTEM SHALL 開催期間がその期間と重なるイベントを表示する。
- **EV-10**: WHEN 利用者が都道府県を指定して検索したとき THE SYSTEM SHALL その都道府県で開催されるイベントを表示する。
- **EV-11**: THE SYSTEM SHALL イベント詳細画面で、全項目と取得元リンクの一覧を表示する。

**US-2**: As a イベント参加者, I want 期間を指定して開催場所を地図で見たい, so that 行ける距離のイベントを探せる.

- **MAP-1**: WHEN 利用者が地図画面で期間を指定したとき THE SYSTEM SHALL その期間に開催されるイベントの会場を、会場ごとのイベント件数とともに一覧表示する。
- **MAP-2**: WHEN 利用者が会場を選んだとき THE SYSTEM SHALL その会場を Google マップ（埋め込み）で表示する。
- **MAP-3**: THE SYSTEM SHALL イベント詳細画面に、開催場所を Google マップで開くリンクを表示する。

### コスプレイヤー

**US-3**: As a コスプレに興味がある人, I want コスプレイヤーを検索してプロフィールを見たい, so that 活動内容や SNS をまとめて知ることができる.

- **CP-1**: WHEN コスプレイヤー収集バッチを実行したとき THE SYSTEM SHALL 対象サイトから、名前・SNS のリンク・経歴・説明文・備考・取得元リンクを抽出して DB に保存する。
- **CP-2**: THE SYSTEM SHALL コスプレイヤー収集をコマンド1つ（バッチ）で実行できる。
- **CP-3**: WHEN 抽出したコスプレイヤーが、既存のコスプレイヤーと名前の類似度 0.9 以上のとき THE SYSTEM SHALL 新しく登録せず既存のコスプレイヤーに統合し、空の項目を補い、SNS のリンクと取得元を追加する。
- **CP-4**: WHEN 利用者がキーワードを入力して検索したとき THE SYSTEM SHALL 名前・説明文・経歴のいずれかにキーワードを含むコスプレイヤーを表示する。
- **CP-5**: THE SYSTEM SHALL コスプレイヤー詳細画面で、名前・SNS のリンク・経歴・説明文・備考・取得元リンクを表示する。

### 収集の共通事項

- **FT-1**: WHEN バッチがページを取得したとき THE SYSTEM SHALL 取得した URL・日時・HTTP ステータス・本文をログとして DB に保存する。
- **FT-2**: IF 取得しようとした URL が取得済みのとき THEN THE SYSTEM SHALL そのページを再取得しない。
- **FT-3**: WHERE バッチに `--force` が指定された場合 THE SYSTEM SHALL 取得済みの URL も再取得する。
- **FT-4**: IF ページの取得に失敗したとき THEN THE SYSTEM SHALL 失敗をログに残して次のページの処理を続ける。

## 非機能要件

- **NF-1（礼儀正しい収集）**: THE SYSTEM SHALL 同じホストへのリクエストを1秒以上の間隔で送り、robots.txt で禁止されたパスは取得しない。
- **NF-2（性能）**: THE SYSTEM SHALL 一覧 API をページ送り（1ページ20件）で返す。
- **NF-3（安全な既定値）**: IF 本番環境（`APP_ENV=production`）で `DJANGO_SECRET_KEY` が未設定のとき THEN THE SYSTEM SHALL 起動を中止する。
- **NF-4（配信）**: THE SYSTEM SHALL フロントエンドを静的ファイルとして出力し、`/apps/cosplay-event-info/` 配下で配信できる。
- **NF-5（XSS 対策）**: THE SYSTEM SHALL 収集した文字列をすべてテキストとして表示し、HTML として解釈しない。リンクは `http`・`https` のものだけを表示する。
