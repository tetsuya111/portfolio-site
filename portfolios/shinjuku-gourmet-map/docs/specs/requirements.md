# 要件定義: 新宿グルメマップ（shinjuku-gourmet-map）

## 前提と仮定

要望（チャットでのヒアリング内容）から、次のとおり推定・判断した。ユーザーへの確認は行っていない。

| # | 仮定・判断 | 根拠 |
| --- | --- | --- |
| A1 | 対象エリアは新宿駅周辺（中心: 新宿駅、半径1.5km程度）とし、中心座標・半径も設定ファイルで変更できるようにする | 「新宿のおすすめの店」。エリアも手動で変えたくなる可能性が高いため |
| A2 | ジャンルはプロジェクト内の設定ファイル（JSON）に「表示名・検索クエリ」を手入力して追加・削除する。初期値は「ラーメン」「カフェ」「居酒屋」など5件程度を用意する | 「ジャンルはプロジェクトのファイルから手動で任意でいれたい」 |
| A3 | 閲覧者はフリーワード検索をしない（検索ボックスを置かない） | 「ユーザーが検索するというよりは、あらかじめクエリを準備して」 |
| A4 | 地図・店舗検索・店舗詳細は Google Maps Platform（Maps JavaScript API と Places API）の機能を使う | 「google mapで作成したい」「基本はgoogle mapの機能を活用する方針でよし」 |
| A5 | ランニングコスト無料は「Google Maps Platform の毎月の無料利用枠内に収める」ことで実現する。サーバーは持たず、静的ファイルとして配信する | 「ランニングコストは無料にしたい」。サーバーを持たなければホスティングも無料枠のある静的ホスティングで足りる |
| A6 | APIキーは `.env` で管理しリポジトリに含めない。ただしブラウザから Google Maps を呼ぶ方式ではキーが配信物に含まれることは避けられないため、Google Cloud 側の「HTTPリファラー制限」「API制限」「1日あたりの上限（クォータ）」で悪用を防ぐ手順を README に書く | 「.envファイルなどで管理」 |
| A7 | 店舗詳細は「店名・住所・評価・口コミ件数・営業時間・電話番号・Webサイト・Googleマップで開くリンク」を表示する | 「ピンをクリックしたら店の詳細を表示」。Googleが提供する範囲の基本情報で足りると判断 |
| A8 | 画面はPC・スマートフォンの両方で閲覧できるようにする | ポートフォリオとして面接官等がスマホで見る可能性があるため |
| A9 | 期間1か月・開発予算30万円は、本リポジトリの成果物としては「1人で数日〜数週間で作れる規模に絞る」という制約として扱う | 要望の期間・予算 |

## 背景・課題

ポートフォリオの閲覧者（採用担当者など）に、地図APIを使った実用的なWebアプリを作れることを短時間で示したい。同時に、作者自身のおすすめ（新宿のラーメン・カフェ等）をジャンル別に地図で紹介できる「自分らしい」題材にしたい。

一般的な地図アプリでは閲覧者が自分で検索語を考える必要があり、作者の「おすすめ」という意図が伝わらない。作者が事前に用意したジャンルを押すだけで、同じ地図上の表示が切り替わる仕組みが必要である。

## ゴール

- 閲覧者が、ジャンルボタンを押す → 地図上にピンが出る → ピンを押すと店の詳細が見える、の一連の操作を迷わず行える。
- 作者が、コードを書き換えずに設定ファイルの編集だけでジャンルを追加・変更・削除できる。
- 運用費用を0円に保つ。

## Non-Goals（やらないこと）

- 閲覧者によるフリーワード検索（A3）
- お気に入り保存・感想メモ・友達との共有・気分タグ・距離順ソート・営業中フィルタ（ブレインストーミングで出たが、ゴールに含まれないため今回は対象外）
- 閲覧者のログイン・ユーザー管理
- 独自の店舗データベースや、作者自身のコメント・評価の登録
- サーバーサイドの実装（APIプロキシ等）
- 本番環境へのデプロイ作業（手順はREADMEに書く）

## 成功指標

| 指標 | 目標値 |
| --- | --- |
| ジャンル選択から地図にピンが表示されるまでの時間 | 通常の回線で3秒以内 |
| ジャンル追加に必要な変更 | 設定ファイル1つへの1項目追加のみ（コード変更0行） |
| 月額の運用費用 | 0円（Google Maps Platform の無料利用枠内） |
| 自動テスト | `npm test` がすべて成功する |

## ユーザーストーリー

- **US-1**: As a ポートフォリオの閲覧者, I want 用意されたジャンルのボタンを押して新宿のお店を地図上で見たい, so that 作者のおすすめを手軽に知れる。
- **US-2**: As a ポートフォリオの閲覧者, I want 地図上のピンを押してお店の詳細を見たい, so that 行ってみたいかどうかを判断できる。
- **US-3**: As a 作者, I want 設定ファイルを編集するだけでジャンルを追加・変更したい, so that コードを触らずに紹介内容を更新できる。
- **US-4**: As a 作者, I want APIキーをリポジトリに含めずに管理し、運用費用を0円に保ちたい, so that 公開しても不正利用や課金の心配がない。

## 機能要件（受け入れ基準）

### FR-1 ジャンル切り替え（US-1）

- **FR-1.1**: THE SYSTEM SHALL 設定ファイルに定義されたすべてのジャンルを、定義順にボタンとして表示する。
- **FR-1.2**: WHEN ページを開いたとき THE SYSTEM SHALL 設定ファイルの先頭のジャンルを選択状態にして、そのクエリで検索する。
- **FR-1.3**: WHEN 閲覧者がジャンルボタンを押したとき THE SYSTEM SHALL そのジャンルのクエリで対象エリアの店舗を検索する。
- **FR-1.4**: THE SYSTEM SHALL 選択中のジャンルボタンを、他のボタンと見た目で区別できる状態にする。
- **FR-1.5**: THE SYSTEM SHALL 閲覧者が自由に検索語を入力する手段を提供しない。

### FR-2 ピン表示（US-1）

- **FR-2.1**: WHEN 検索結果を受け取ったとき THE SYSTEM SHALL 各店舗の位置に1つずつピンを表示する。
- **FR-2.2**: WHEN ジャンルを切り替えたとき THE SYSTEM SHALL 直前のジャンルのピンを地図から取り除く。
- **FR-2.3**: THE SYSTEM SHALL ジャンルを切り替えても同じ地図を使い続ける（ページ遷移や地図の再生成をしない）。
- **FR-2.4**: WHEN ピンを表示したとき THE SYSTEM SHALL すべてのピンが画面に収まるように地図の表示範囲を調整する。
- **FR-2.5**: WHILE 検索中である間 THE SYSTEM SHALL 読み込み中であることを表示する。
- **FR-2.6**: THE SYSTEM SHALL 表示中のジャンル名と件数を表示する。
- **FR-2.7**: IF 検索結果が0件だった場合 THEN THE SYSTEM SHALL 「お店が見つかりませんでした」旨を表示する。
- **FR-2.8**: IF 検索に失敗した場合 THEN THE SYSTEM SHALL エラーメッセージを表示し、他のジャンルボタンは引き続き押せる状態を保つ。
- **FR-2.9**: WHEN 検索中に別のジャンルが押されたとき THE SYSTEM SHALL 最後に押されたジャンルの結果だけを表示する。

### FR-3 店舗詳細（US-2）

- **FR-3.1**: WHEN 閲覧者がピンを押したとき THE SYSTEM SHALL その店舗の詳細を表示する。
- **FR-3.2**: THE SYSTEM SHALL 詳細に店名・住所を表示する。
- **FR-3.3**: WHERE 評価・口コミ件数・営業時間・電話番号・Webサイトの情報がある場合 THE SYSTEM SHALL それらを詳細に表示する（ない項目は表示しない）。
- **FR-3.4**: THE SYSTEM SHALL 詳細に「Googleマップで開く」リンクを表示し、新しいタブで開く。
- **FR-3.5**: WHEN 閲覧者が詳細の「閉じる」を押したとき THE SYSTEM SHALL 詳細を閉じる。
- **FR-3.6**: WHEN ジャンルを切り替えたとき THE SYSTEM SHALL 表示中の詳細を閉じる。
- **FR-3.7**: WHEN ピンを押したとき THE SYSTEM SHALL 押されたピンを他のピンと見た目で区別できる状態にする。

### FR-4 設定ファイル（US-3）

- **FR-4.1**: THE SYSTEM SHALL ジャンル（表示名・検索クエリ）と対象エリア（中心座標・検索半径・初期ズーム）を1つの設定ファイルから読み込む。
- **FR-4.2**: IF 設定ファイルの内容が不正（ジャンルが0件、必須項目の欠落、ID重複、座標が範囲外など）である場合 THEN THE SYSTEM SHALL 原因となる項目を示すエラーメッセージを表示する。

### FR-5 APIキー管理（US-4）

- **FR-5.1**: THE SYSTEM SHALL Google Maps のAPIキーを `.env` ファイル（環境変数）から読み込む。
- **FR-5.2**: THE SYSTEM SHALL `.env` ファイルをリポジトリの管理対象外にする。
- **FR-5.3**: IF APIキーが設定されていない場合 THEN THE SYSTEM SHALL 地図の代わりに設定方法を案内するメッセージを表示する。
- **FR-5.4**: IF 地図の読み込みに失敗した場合 THEN THE SYSTEM SHALL 失敗した旨のメッセージを表示する。

## 非機能要件

- **NFR-1（コスト）**: 同じジャンルを同じ閲覧セッション中に再度選んだときは、Google への再検索を行わない。1回の検索で取得する店舗数は最大20件とする。
- **NFR-2（セキュリティ）**: README に、APIキーへの「HTTPリファラー制限」「API制限」「1日あたりのリクエスト上限」の設定手順を記載する。
- **NFR-3（セキュリティ）**: Google から受け取った店舗情報は、HTMLとして解釈せず文字列として表示する（スクリプト注入を防ぐ）。
- **NFR-4（性能）**: ジャンル選択から地図にピンが表示されるまで、通常の回線で3秒以内とする。
- **NFR-5（対応環境）**: 最新版の Chrome・Edge・Safari・Firefox（PC・スマートフォン）で表示・操作できる。幅375pxの画面でも横スクロールなしで操作できる。
- **NFR-6（アクセシビリティ）**: ジャンルボタンと詳細の「閉じる」はキーボードで操作でき、選択状態を支援技術に伝える。
- **NFR-7（帰属表示）**: Google の利用規約に従い、Google の地図・店舗情報であることの表示（地図上のGoogleロゴ等）を消さない。
- **NFR-8（保守性）**: `npm test`・`npm run lint`・`npm run build` がすべて成功する。
