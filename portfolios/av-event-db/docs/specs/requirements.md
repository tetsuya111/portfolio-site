# 要件定義: AVイベント情報DBサイト（av-event-db）

元の機能要望: [memo/AVイベントのDBサイト.md](../../../../memo/AVイベントのDBサイト.md)

## 前提と仮定

ユーザーへの確認を行わずに作成したため、次の仮定を置いた。覆したい場合はこの節から見直す。

- **掲載内容は健全な範囲に限る**: 扱うのはイベントの日時・場所・出演者名・リンクなどの告知情報のみ。画像・動画・性的な描写を含むテキストは収集・表示しない。サイト利用前に18歳以上かを確認する年齢確認画面を置く。
- **取得対象サイトのHTML構造は未調査**: 作成時に対象サイトへアクセスしていない。サイトごとの抽出ルール（CSSセレクタ）は設定ファイルに外出しし、実サイトに合わせてコードを変えずに調整できるようにする。テストは構造を仮定したHTMLフィクスチャで行う。
- **「再度同じページから情報を取得しない」の対象は詳細ページ**: 一覧ページ（`/top/`・`/new_event/` など）は新着を知るため毎回取得し、そこから辿る個々のイベント詳細ページを取得済みなら再取得しない。一覧ページの取得も記録は残す。
- **AIによる開催場所の補完はAnthropic Claude APIを使う**: APIキーが未設定のときは、表記ゆれを整える規則ベースの正規化だけを行い、処理は止めない。
- **地図表示の座標はGoogle Geocoding APIで取得する**: キー未設定のときは座標なしで保存し、地図画面では座標のある会場だけをピン表示し、座標のない会場は「Google マップで開く」リンクの一覧で示す。
- **利用者は閲覧者のみ**: 会員登録・ログイン・管理画面は作らない。DBへの追加はバッチ（管理コマンド）だけで行う。
- **配置**: 既存の `portfolios/inventory-management/` と同じく、フロントエンドは静的出力・`/apps/av-event-db` 配下での配信を前提にする。

## 背景・課題

AV女優のイベント（サイン会・撮影会・トークイベントなど）の情報は複数のサイトに散らばっており、横断して探せる場所がない。既存の告知サイトは一覧表示だけの簡素なものが多く、「この女優のイベント」「この期間に東京で開かれるイベント」を探すには複数サイトを見比べる必要がある。

## ゴール

- 複数サイトのイベント情報を1つのDBに重複なく集め、1つのサイトで検索・閲覧できるようにする。
- 期間を指定して、開催場所を地図上で確認できるようにする。

## Non-Goals（やらないこと）

- 会員機能・お気に入り・通知
- 管理画面からの手入力・編集（Django admin は開発者用に有効化するが、要件としては扱わない）
- 画像・動画など、告知テキスト以外のコンテンツの収集・表示
- 対象サイトの定期実行のスケジューリング（cron などで管理コマンドを呼ぶ運用に任せる）
- チケット購入・予約の代行

## 成功指標

- 同一イベントが複数サイトに載っていても、DB上は1件にまとまる（重複判定テストケースの正答率100%）。
- 取得済みの詳細ページへのHTTPリクエストが、2回目以降のバッチ実行で0件になる。
- 検索APIが1,000件のイベントに対して1秒以内に応答する。

## ユーザーストーリーと受け入れ基準

### REQ-1 イベント情報の取得とDB登録（バッチ）

As a サイト運営者, I want 対象サイトからイベントの予定をバッチで取り込みたい, so that 手作業なしでDBを最新に保てる。

- REQ-1.1 WHEN 運営者が取り込みバッチを実行する THE SYSTEM SHALL 設定された対象サイトの一覧ページからイベント詳細ページを辿り、イベントをDBに登録する。
- REQ-1.2 THE SYSTEM SHALL 各イベントについて、イベント名・参加するAV女優の名前・リンク・開催場所・開催日時・概要・備考・取得元リンクを保存する。
- REQ-1.3 WHEN 運営者が取り込み対象のサイトを指定してバッチを実行する THE SYSTEM SHALL 指定したサイトだけを取り込む。
- REQ-1.4 IF 1つのページの取得・解析に失敗した THEN THE SYSTEM SHALL そのページを失敗として記録し、残りのページの処理を続ける。
- REQ-1.5 THE SYSTEM SHALL 同一サイトへのリクエストの間隔を1秒以上あける。
- REQ-1.6 IF 対象サイトの robots.txt が取得対象のURLを禁止している THEN THE SYSTEM SHALL そのURLを取得しない。

### REQ-2 取得ページのログと再取得の防止

As a サイト運営者, I want 取得したページを記録し同じページを取り直さないようにしたい, so that 対象サイトへの負荷と処理時間を抑えられる。

- REQ-2.1 WHEN ページを取得した THE SYSTEM SHALL URL・取得日時・HTTPステータス・本文・処理結果を記録する。
- REQ-2.2 IF 取得しようとしたイベント詳細ページが取得成功として記録済みである THEN THE SYSTEM SHALL そのページへHTTPリクエストを送らない。
- REQ-2.3 IF 記録済みのイベント詳細ページの前回の取得が失敗だった THEN THE SYSTEM SHALL そのページを再取得する。

### REQ-3 重複イベントの統合

As a 閲覧者, I want 同じイベントが1件だけ表示されてほしい, so that 複数サイトに載っているイベントを見比べずに済む。

- REQ-3.1 WHEN 取り込んだイベントが、開催日が同じでイベント名がレーベンシュタイン距離に基づく類似度でしきい値以上の既存イベントと一致する THE SYSTEM SHALL 新しいイベントを作らず既存イベントに統合する。
- REQ-3.2 WHEN イベントを統合する THE SYSTEM SHALL 取得元リンクを既存イベントに追加し、すべての取得元リンクを保持する。
- REQ-3.3 WHEN イベントを統合する THE SYSTEM SHALL 既存イベントの空の項目を新しい情報で補い、参加女優を和集合にする。
- REQ-3.4 IF 開催日が異なる THEN THE SYSTEM SHALL イベント名が一致していても別イベントとして登録する。

### REQ-4 開催場所の補完・正規化

As a 閲覧者, I want 開催場所の表記がそろっていてほしい, so that 同じ会場のイベントをまとめて探せ、地図にも正しく表示される。

- REQ-4.1 WHEN 新しい開催場所の文字列を取り込む THE SYSTEM SHALL AIで会場名・住所・都道府県を補完・正規化して会場として保存する。
- REQ-4.2 WHEN 正規化後の会場名と住所が既存の会場と一致する THE SYSTEM SHALL 既存の会場を再利用する。
- REQ-4.3 IF AIが利用できない（APIキー未設定・API失敗） THEN THE SYSTEM SHALL 規則ベースの正規化（全角半角・空白の統一）だけを行って保存する。
- REQ-4.4 WHERE 地図用のAPIキーが設定されている THE SYSTEM SHALL 会場の住所から緯度経度を取得して保存する。

### REQ-5 イベントの検索・閲覧

As a 閲覧者, I want イベントをキーワード・女優名・期間・都道府県で検索したい, so that 行きたいイベントを素早く見つけられる。

- REQ-5.1 THE SYSTEM SHALL イベントの一覧を開催日時の昇順で表示する。
- REQ-5.2 WHEN 閲覧者がキーワードを入力する THE SYSTEM SHALL イベント名・概要・備考・女優名・会場名のいずれかに含むイベントだけを表示する。
- REQ-5.3 WHEN 閲覧者が開始日・終了日を指定する THE SYSTEM SHALL 開催期間がその範囲と重なるイベントだけを表示する。
- REQ-5.4 WHEN 閲覧者が都道府県を指定する THE SYSTEM SHALL その都道府県の会場のイベントだけを表示する。
- REQ-5.5 WHEN 閲覧者がイベントを選ぶ THE SYSTEM SHALL そのイベントのすべての項目と取得元リンクを表示する。
- REQ-5.6 THE SYSTEM SHALL 一覧を1ページ20件でページ分割する。
- REQ-5.7 IF 条件に合うイベントがない THEN THE SYSTEM SHALL 該当なしのメッセージを表示する。

### REQ-6 期間指定の地図表示

As a 閲覧者, I want 指定した期間のイベント会場をGoogle マップで見たい, so that 行ける場所のイベントを地理的に探せる。

- REQ-6.1 WHEN 閲覧者が地図画面で期間を指定する THE SYSTEM SHALL その期間に開催されるイベントの会場をGoogle マップ上にピンで表示する。
- REQ-6.2 WHEN 閲覧者がピンを選ぶ THE SYSTEM SHALL その会場で期間内に開催されるイベントの一覧を表示する。
- REQ-6.3 IF 期間内のイベントの会場に緯度経度がない THEN THE SYSTEM SHALL その会場をGoogle マップの検索リンク付きの一覧で表示する。
- REQ-6.4 IF Google マップのAPIキーが設定されていない THEN THE SYSTEM SHALL 地図の代わりに全会場をGoogle マップの検索リンク付きの一覧で表示する。

### REQ-7 年齢確認

As a サイト運営者, I want 閲覧前に年齢確認をしたい, so that 18歳未満の利用を防ぐ意思表示ができる。

- REQ-7.1 WHEN 年齢確認を済ませていない閲覧者がページを開く THE SYSTEM SHALL 18歳以上かを確認する画面を表示し、内容を表示しない。
- REQ-7.2 WHEN 閲覧者が18歳以上と回答する THE SYSTEM SHALL 内容を表示し、回答をブラウザに保存して次回から確認を省略する。

## 非機能要件

- NFR-1 性能: 検索APIは1,000件のイベントに対して1秒以内に応答する。
- NFR-2 セキュリティ: APIは読み取り専用（GET）とし、書き込み系のエンドポイントを公開しない。APIキーはソースに書かず環境変数で渡す。
- NFR-3 安全性: 取得したHTMLの文字列は画面にHTMLとして埋め込まず、テキストとして表示する。外部リンクは `http`/`https` のみ許可する。
- NFR-4 保守性: 対象サイトの抽出ルールはコードを変えずに設定ファイルで調整できる。
