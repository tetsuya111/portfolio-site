# profile.md 作成のプロンプト

スキルシートから抽出したテキスト（以下「スキルシート」）と既存の profile.md をもとに、ポートフォリオサイトの自己紹介ページに載せる profile.md の全文を作る。このファイルは**公開サイトにそのまま表示される**。

## 出力のフォーマット

次の形をそのまま守る。frontmatter の項目名・見出しの文言・見出しの順番は変えない。

```markdown
---
name: <氏名>
role: <肩書き>
summary: <1〜2文の要約>
links:
  - label: <リンク名>
    url: <https:// で始まる URL>
---

## 自己紹介

<2〜4文の自己紹介>

## 経歴

- <開始年>年〜<終了年>年: <内容>
- <開始年>年〜: <内容>

## スキル

- <分類ごとの技術を / で区切る>
```

- frontmatter の値に `:`・`#`・`"`・`'` を含むとき、記号（`-`・`[` など）で始まるとき、数字・日付だけのときは、ダブルクォートで囲む（例: `role: "PM: 兼 エンジニア"`）。中の `"` は `\"` にする。
- `summary` が書けなければ行ごと省く。`links` が1件もなければ行ごと省く。
- 本文に `#`（h1）は使わない。3つの見出しの下に、必要なら `###` の小見出しを足してよい。
- 出力は profile.md の全文だけにする（前置き・説明・コードフェンスを付けない）。

## 項目の読み取り方

スキルシートの書式は人によって違う。列名・見出しの言い回しにこだわらず、意味で対応づける。

| profile.md | スキルシートで探すもの |
|---|---|
| `name` | 氏名。イニシャル・ニックネームだけならそのまま書く（フルネームを推測しない） |
| `role` | 肩書き・職種・希望ポジション（例: 「フリーランス Web エンジニア」「バックエンドエンジニア」） |
| `summary` | 強み・得意分野・自己PRの要点を1〜2文、です・ます調で |
| `links` | GitHub・ブログ・Qiita・Zenn・ポートフォリオなどの http(s) URL |
| 自己紹介 | 自己PR・得意分野・仕事の進め方。2〜4文、です・ます調で |
| 経歴 | 職務経歴・案件一覧。**古い順**に、期間（年の範囲）と、業種・役割・担当工程・主な技術を1行に要約する。案件が多ければ、同じ時期・同じ種類のものをまとめて10行以内にする |
| スキル | 言語・フレームワーク・DB・クラウド・ツールを分類ごとに1行（例: `- TypeScript / React / Astro`）。経験年数・レベルが書かれていれば `（5年）` のように添えてよい |

## 載せない情報（必ず守る）

スキルシートは応募先に渡す前提の書類で、公開してはいけない情報を含む。次の情報は、どこにも書かない。

- 電話番号・メールアドレス・住所・最寄り駅
- 生年月日・年齢・性別・国籍・家族構成
- 顔写真・SNS の個人アカウント（GitHub などの技術系リンクは載せてよい）
- 取引先・顧客企業・エンド企業の実名と、案件のプロダクト名・社内システム名
  - 業種と規模で書く（例: 「大手通信会社の顧客管理システム」→「通信業界の顧客管理システム」、「〇〇銀行」→「金融機関」）
- 単価・希望単価・稼働条件・退職理由

## 引き継ぎと推測の禁止

- スキルシートから読み取れない項目は、既存の profile.md の値を使う（`links` は特に、スキルシートに URL がなければ既存のものをそのまま残す）。
- 既存の profile.md が雛形（「ここに自己紹介を書く」などの文言）のままで、スキルシートにもない項目は、その項目を省くか、スキルシートの事実だけから書く。
- スキルシートにない経歴・技術・実績・数値を足さない。表現を整えるのはよいが、事実を盛らない。
