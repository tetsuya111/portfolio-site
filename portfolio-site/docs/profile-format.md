# profile.md の本文の書式

自己紹介ページ（`/about/`）は、`src/content/profile/profile.md` の本文がこのドキュメントの書式で書かれていると、経歴をタイムライン、スキル・資格をタグで表示する。書式から外れると、本文を Markdown のまま表示する（内容は欠けないが、タイムラインやタグの表示にならない）。

- frontmatter（`name`・`role`・`summary`・`links`）の項目と、更新のしかた（直接編集・管理画面）は [content-files.md](content-files.md#自己紹介経歴profile) を参照。
- 読み取りの処理は [`src/lib/profile-body.ts`](../src/lib/profile-body.ts) の `parseProfileBody()`、表示は [`src/pages/about.astro`](../src/pages/about.astro)。
- 色分けに使う色は、テーマの `spectrum-1`〜`spectrum-4`（[themes.md](themes.md)）。

## 全体の形

```markdown
---
name: 山田 太郎
role: フリーランス Web エンジニア
summary: Web アプリケーションの設計から AWS 上での運用までを一人で担当します。
---

## 自己紹介

システム開発からクラウド構築まで対応できます。

学生のころからプログラミングを学び、…

## 経歴

- 2020年〜2024年: 事業会社で Web サービスの開発（Python / Django による API 開発、AWS 環境の構築）
- 2024年〜: フリーランスとして独立（React / Next.js、Go）

## スキル

- Python / Go / TypeScript
- Django / React / Next.js
- AWS / Docker / Linux（RHEL・Ubuntu）

### 資格

- AWS Certified Solutions Architect – Associate / CCNA
- 基本情報技術者
```

## 見出し

| 見出し | 中身 | ページでの表示 |
|---|---|---|
| `## 自己紹介` | 段落（空行で区切る） | 「自己紹介」の節。1段落目は大きめのリード文 |
| `## 経歴` | 箇条書き（1行1件） | 縦のタイムライン。上から順に4色で色分け |
| `## スキル` | 箇条書き（1行1まとまり） | まとまりごとの色帯付きカード（2列） |
| `### 資格` | 箇条書き | `## スキル` の下に、✓ 付きのバッジ |

- 使える見出しはこの4つだけで、**この順に**書く。どれかを省いてもよい（省いた節は表示しない）。
- `### 資格` は `## スキル` の直後（スキルの箇条書きの後）に置く。
- 本文は最初の見出しから始める（見出しより前に文を書かない）。
- 見出しだけで中身のない節は書かない。

## 各節の書き方

### 自己紹介

- 普通の文章を段落で書く。段落の間は空行を1行入れる。
- 段落の中の改行は、ページでは空白として表示される（Markdown と同じ）。
- 箇条書き・番号付きリスト・字下げ（行頭の空白）は使わない。

### 経歴

1行1件で、`- <期間>: <内容>` と書く。ページには本文の順に並ぶ（新しい順・古い順は書いた順のまま）。

```markdown
- 2023年〜2025年: 自治体向け AI アプリの開発（Dify による AI 開発、Python / Django での連携、Docker・AWS 環境の構築）
```

- **期間**: 最初の `:`（全角の `：` も可）より前。30文字以内。等幅の文字で色付きで表示する。
- **内容**: `:` の後。末尾が `（…）`（半角の `(…)` も可）なら、括弧より前を見出し、括弧の中を `、` で区切った各項目を「担当内容」のタグにする。
  - 上の例は、見出し「自治体向け AI アプリの開発」、タグ「Dify による AI 開発」「Python / Django での連携」「Docker・AWS 環境の構築」になる。
  - 括弧の中に括弧があってもよい。内側の括弧の中の `、` では区切らない（`React（Next.js、Remix）` は1つのタグ）。
  - 見出しの途中の括弧（例: `営業支援ツール（ブラウザ拡張機能）の開発（…）`）はそのまま見出しに残る。区切るのは末尾の括弧だけ。
  - 末尾が括弧でなければ、内容全体が見出しになり、タグは出ない。

### スキル

1行1まとまりで、技術を ` / `（前後に空白のあるスラッシュ）で区切る。

```markdown
- Python / Go / TypeScript
- AWS / Docker / Linux（RHEL・Ubuntu）
```

- 各技術がタグ（`#Python` のように表示）になり、1行が1枚のカードになる。カードは上から順に4色で色分けする。
- 空白のない `/`（例: `TCP/IP`・`C/C++`）では区切らない。
- 分類名（「言語」など）を書く欄はない。同じ分類の技術を1行にまとめると見やすい。
- トップページの「スキル」（`src/content/skills/`）とは別のもの（[content-files.md](content-files.md#スキルskills)）。

### 資格

スキルと同じく、1行に ` / ` で区切って書く。行の区切りは表示に関係なく、すべての資格を1つずつバッジにして並べる。

## Markdown 表示に戻る条件

次のどれかに当たると、ページ全体が従来の表示（本文をそのまま Markdown で描く）になる。新しいデザインで表示したいときは避ける。

| 条件 | 例 |
|---|---|
| 上の4つ以外の見出し、見出しの重複、順序違い | `## 趣味`、`#### 補足`、`## スキル` の後に `## 経歴` |
| 見出しより前の文、中身のない節 | 冒頭の挨拶文、`## 経歴` の下が空 |
| 経歴・スキル・資格に箇条書きでない行がある | 補足の文、入れ子の箇条書き（`  - …`・`- 1. …`） |
| 経歴の行に `:` がない、期間が30文字を超える | `- 事業会社で開発` |
| 自己紹介に箇条書き・番号付きリスト・字下げ・見出しの下線がある | `- …`、`1. …`、行頭の空白、`===`・`---` だけの行 |
| Markdown の装飾・HTML | `[リンク](…)`、`**強調**`、`` `コード` ``、`_`、`~`、`\|`、`<b>`、`[`・`]` |
| 自動でリンク・記号に置き換わるもの | URL（`https://…`・`www.…`）、メールアドレス、半角の `"`・`'`、`--`、`...` |
| HTML の文字参照・強制改行 | `&amp;`・`&#169;`、行末の2つ以上の空白 |

- 文中の `#`・`&`・`@` は問題ない（`C#`・`R&D`・`@mention` はそのまま表示できる）。行頭の `#`（見出し以外）は不可。
- 全角の記号（`“”`・`‘’`・`〜`・`…`・`–`）は使える。引用符・ダッシュ・三点リーダーを書きたいときは全角を使う。

## 確認のしかた

- `npm test -- profile-body`: `tests/profile-body.test.ts` が、実際の `profile.md` がこの書式で読めることを確かめる（読めないと失敗する）。
- `npm run test:build`: ビルドした `/about/` に、経歴の期間・見出し・担当内容、スキル・資格のタグがすべて出ていることを確かめる。
- 見た目は `npm run dev` で `http://localhost:4321/about/` を開いて確認する。タイムラインやタグにならず文章だけが並ぶときは、上の「Markdown 表示に戻る条件」に当たっている。
