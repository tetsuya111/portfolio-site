# コンテンツファイル（自己紹介・ポートフォリオ・記事）

サイトに表示する自己紹介・ポートフォリオ・記事は、すべて `src/content/` 配下の md ファイルで管理する。ページのコードを変えずに、ファイルを追加・編集するだけでサイトに反映される。このドキュメントは、各ファイルの置き場所・書式・追加方法・検証ルールをまとめる。

- frontmatter（先頭の `---` で囲んだ部分）がデータ、その後ろの本文が Markdown の内容になる。
- 項目の定義（スキーマ）は [`src/lib/schemas.ts`](../src/lib/schemas.ts)。ビルド時と、コマンド・管理画面で保存するときに同じスキーマで検証する。
- 本番に反映するには、変更をコミットして `main` に push する（CodeBuild がビルド・デプロイする。[../infra/README.md](../infra/README.md)）。

## 種類と追加方法の一覧

| 種類 | 置き場所 | 件数 | ファイルを直接編集 | コマンド | 管理画面（`npm run dev` 中のみ） |
|---|---|---|---|---|---|
| 自己紹介・経歴 | `src/content/profile/profile.md` | 1件固定 | ○ | — | ○ 編集（全文を置き換え） |
| ポートフォリオ | `src/content/portfolios/<スラッグ>.md` | 何件でも | ○ | ○ `npm run portfolio:new` | ×（サイト上からは追加できない） |
| 記事 | `src/content/articles/<スラッグ>.md` | 何件でも | ○ | — | ○ 新規作成（フォーム入力／md アップロード） |

## 共通のルール

### ファイル名（スラッグ）

ファイル名から拡張子 `.md` を除いた部分がスラッグになり、URL に使われる（例: `articles/hello-world.md` → `/articles/hello-world/`）。

- 英小文字・数字を、1つのハイフンでつないだ 1〜64 文字にする（正規表現 `^[a-z0-9]+(?:-[a-z0-9]+)*$`）。
  - よい例: `hello-world`、`my-app-2`
  - だめな例: `Hello-World`（大文字）、`my_app`（アンダースコア）、`a--b`（ハイフンの連続）、`-a`、`日本語`
- コマンドと管理画面はこのルールに合わないスラッグを拒否する。ファイルを直接置く場合は検査されないため、自分で守る。なお大文字は小文字に変換されて URL になる（`My-App.md` → `/portfolios/my-app/`）。
- **サブフォルダに置かない**。`articles/2026/foo.md` のように置くと、ビルドが `Missing parameter: slug` で失敗する。
- スラッグを変えると URL も変わる（公開済みのリンクは切れる）。

### frontmatter の書き方

- YAML で書く。値に `:`・`#`・`"` などの記号を含むときは、ダブルクォートで囲む（例: `title: "Astro: はじめに"`）。
- 日付は `YYYY-MM-DD`（例: `2026-11-13`）。存在しない日付（`2026-13-40` など）はエラーになる。
- URL は `http://` または `https://` で始まるものだけを受け付ける（`javascript:` などは拒否）。
- スキーマにない項目を書いても、エラーにはならず無視される。
- 必須項目がない・型が違う場合、ビルド（`npm run build`・`npm run dev`）はエラーで止まる。コマンドと管理画面では保存を拒否し、ファイルは変更しない。

### 本文

- Markdown で書く。見出し・リスト・リンク・コードブロック・表などが使え、ページでは `prose` スタイル（Tailwind CSS typography）で整形される。
- 見出しは `##` から始める。ページのタイトル（`<h1>`）は frontmatter の `title`（自己紹介は `name`）から自動で出る。
- 画像の置き場所・書き方は、まだ決めていない（動作未確認）。

## 自己紹介・経歴（profile）

`src/content/profile/profile.md` の1ファイルだけ。このファイルがないとビルドが失敗する。

| 項目 | 必須 | 型 | 表示される場所 |
|---|---|---|---|
| `name` | ○ | 文字列 | トップページの冒頭（いちばん大きい見出し）、自己紹介ページの見出し |
| `role` | ○ | 文字列 | 氏名の下（肩書き） |
| `summary` | | 文字列 | トップページの一言紹介、トップと自己紹介ページの `<meta name="description">` |
| `links` | | `{ label, url }` の配列 | 自己紹介ページの氏名の下にリンクとして並ぶ（別タブで開く）。`url` は http/https のみ |

本文は自己紹介ページ（`/about/`）に表示する。経歴・スキルなどを書く。

```markdown
---
name: 山田 太郎
role: フリーランス Web エンジニア
summary: Web アプリケーションの設計から AWS 上での運用までを一人で担当します。
links:
  - label: GitHub
    url: https://github.com/xxxx
---

## 自己紹介

...

## 経歴

- 2020年〜2024年: 事業会社で Web サービスの開発に従事
- 2024年〜: フリーランスとして独立
```

### 更新のしかた

- **ファイルを直接編集する**。
- **管理画面**: `npm run dev` で開発サーバーを起動し、`http://localhost:4321/admin/profile/` を開く。ファイルの全文がテキスト欄に表示されるので、編集して「保存」を押す。保存すると `profile.md` 全体が置き換わる（`name`・`role` がなければ保存されない）。

## ポートフォリオ（portfolios）

`src/content/portfolios/<スラッグ>.md`。1件1ファイル。

| 項目 | 必須 | 型 | 既定値 | 表示・用途 |
|---|---|---|---|---|
| `title` | ○ | 文字列 | — | タイル（トップ・一覧）と詳細ページの見出し |
| `tags` | | 文字列の配列 | `[]` | タイルと詳細ページにタグとして表示 |
| `url` | | URL（http/https） | なし | 指定するとタイルに「ポートフォリオのURL」ボタンが出る（別タブで開く）。詳細ページにもリンクが出る |
| `date` | | 日付 | なし | 一覧の並び順（新しい順）。指定のないものは最後に、タイトル順で並ぶ。画面には表示しない |

本文はポートフォリオの詳細ページ（`/portfolios/<スラッグ>/`）に表示する。一覧はトップページとポートフォリオ一覧ページ（`/portfolios/`）のタイルで、タイトル・タグ・URL ボタンだけを表示する。

```markdown
---
title: このポートフォリオサイト
tags:
  - Astro
  - AWS
url: https://example.com/
date: 2026-11-13
---

## 概要

...
```

### 追加のしかた

サイト上からは追加できない。次のどちらかで追加する。

**コマンド（おすすめ）**: 必要な項目がそろった md を作る。

```bash
npm run portfolio:new -- --slug my-app --title "My App" --tags "Astro,AWS" --url https://example.com
```

| 引数 | 必須 | 内容 |
|---|---|---|
| `--slug` | ○ | スラッグ。日本語のタイトルからは自動で作らないので必ず指定する |
| `--title` | ○ | タイトル |
| `--tags` | | カンマ区切り。前後の空白と空の要素は取り除く |
| `--url` | | http/https の URL |

- `date` には実行した日付（ローカル時刻）が入り、本文には `## 概要` の雛形が入る。作成後に本文を書き足す。
- 同じスラッグのファイルが既にある、引数が足りない・不正、知らない引数がある場合は、何も作らずに理由を表示して終了コード 1 で終わる。

**ファイルを直接置く**: 上の書式で `src/content/portfolios/` に md を置く。

## 記事（articles）

`src/content/articles/<スラッグ>.md`。1件1ファイル。

| 項目 | 必須 | 型 | 既定値 | 表示・用途 |
|---|---|---|---|---|
| `title` | ○ | 文字列 | — | 一覧と詳細ページの見出し |
| `date` | ○ | 日付 | — | 一覧の並び順（新しい順）。`YYYY/MM/DD` 形式で表示 |
| `tags` | | 文字列の配列 | `[]` | 一覧と詳細ページにタグとして表示 |
| `description` | | 文字列 | なし | 記事一覧の説明文、詳細ページの `<meta name="description">` |
| `draft` | | 真偽値 | `false` | `true` にすると公開しない（一覧・トップの最新記事に出ず、詳細ページも生成されない） |

本文は記事の詳細ページ（`/articles/<スラッグ>/`）に表示する。記事一覧（`/articles/`）と、トップページの「最新の記事」（新しい順に3件）にも出る。

```markdown
---
title: はじめての記事
date: 2026-11-13
tags: [お知らせ]
description: ポートフォリオサイトを公開しました。
draft: false
---

本文
```

### 追加のしかた

**ファイルを置く**: 上の書式で `src/content/articles/` に md を置く。まとめて何件でも置ける。

**管理画面**: `npm run dev` 中に `http://localhost:4321/admin/articles/new/` を開く。

- **フォームで入力**: スラッグ・タイトル・日付・タグ（カンマ区切り）・説明・下書き・本文を入力して保存する。入力値から md が作られる。
- **md ファイルをアップロード**: 手元の md ファイルを選んで保存する。スラッグの欄が空ならファイル名（`.md` を除く）をスラッグにする。frontmatter に `title`・`date` が必要。

どちらも新規作成だけで、同じスラッグの記事が既にあると保存しない（上書きしない）。既存の記事を直したいときは、ファイルを直接編集する。

## 管理画面の保存の仕組みと制限

管理画面は `npm run dev` のときだけ使える。本番サイト（`npm run build` の成果物）には含まれない。

| 操作 | API | 成功 | 主な失敗 |
|---|---|---|---|
| 自己紹介の保存 | `PUT /__admin/api/profile` | 200 | 400（frontmatter が不正） |
| 記事の作成 | `POST /__admin/api/articles` | 201 | 400（スラッグ・frontmatter が不正）、409（同じスラッグが既にある） |

- 次の送信は拒否する: 別のサイトのページからの送信（Origin がサーバーと違う、403）、JSON 以外（415）、本文が 1 MB を超えるもの（413）。
- 保存すると開発サーバーがファイルの変更を検知し、公開ページの表示もすぐ更新される。
- 開発サーバーは localhost でだけ待ち受ける。`--host` を付けて外部に公開しないこと（管理画面には認証がない）。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| `npm run build` が frontmatter のエラーで止まる | エラーに出ているファイルの必須項目（profile: `name`・`role`、記事: `title`・`date`、ポートフォリオ: `title`）と、日付・URL の形式 |
| `Missing parameter: slug` でビルドが止まる | md をサブフォルダに置いていないか |
| 記事が一覧に出ない | `draft: true` になっていないか。`date` が意図した日付か（並び順） |
| ポートフォリオに URL ボタンが出ない | `url` が http/https で始まっているか |
| 管理画面で「同じスラッグの記事が既にあります」 | 別のスラッグにするか、既存のファイルを直接編集する |
| 管理画面で 403 になる | 開いているページと送信先のホスト（ポート番号を含む）が同じか |
